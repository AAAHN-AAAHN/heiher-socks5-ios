# UDP compatibility and adaptive datagram buffers

## Purpose and scope

This feature preserves complete SOCKS UDP messages, correct address reporting and peer isolation while retaining the native engine's compact association and task model. It also handles UDP-over-TCP framing without treating an incomplete byte stream as a completed datagram.

The branch adds native transport behavior to the shared baseline. It does not implement traffic counters, persistent settings, background services or a new SOCKS protocol. A datagram remains one message; larger payloads are not split into independent UDP messages. The configured fixed-port policy is retained, including its explicit multiple-unknown-peer limitation.

## Functional behavior

### Association setup and source identity

A client may request UDP ASSOCIATE without knowing its UDP source port. The server does not attempt to connect the relay socket to port zero. It binds the relay and reports its usable address and assigned port. With a known client endpoint, the existing connected-socket path remains available.

For an unknown endpoint, the first accepted datagram must match the TCP control peer's IP and pass the SOCKS header and address checks before its source port is learned. Subsequent datagrams must match the established endpoint. Queued packets are checked individually, including packets queued before the UDP socket became connected. Discarding a batch of foreign packets does not incorrectly signal that the entire socket queue is empty.

A length-prefixed NAME destination must be nonempty and preserve its complete identity when passed to native string-based address lookup. After checking that the declared address bytes are present, the receiver rejects an empty name or NUL bytes within it. A malformed name cannot establish the previously unknown peer port, even when its prefix alone names a valid destination. Zero bytes in the following port field remain valid. The shared address converter and both public UDP send paths enforce the same name rule for direct callers. The shared C-string constructor accepts lengths 1 through 255, bounds its scan to 256 bytes and rejects invalid input before changing its output. Its native client constructor propagates rejection before allocating an object.

IPv4, IPv4-mapped IPv6, native IPv6 and address scope are normalized for the native APIs and SOCKS address representation. The source address in an encapsulated UDP reply describes the actual remote sender. Address conversion preserves complete IPv6 storage and respects strict-aliasing requirements rather than reinterpreting incompatible structures in place. Shared destination conversion retains an IPv6 scope returned by the existing resolver and clears a previous scope for an unscoped IPv4 or IPv6 destination, including when callers reuse an output address. Scoped NAME text uses the existing resolver's complete socket-address result, including on Darwin. The requested port remains unchanged; no separate zone parser is added.

A successful CONNECT response reports the outgoing socket's actual local address and assigned port, obtained after connection succeeds. Failure to obtain that endpoint produces a failure response. The destination address remains available to the existing connect path before the response address is obtained.

The TCP request header requires version 5 and a zero reserved byte before address resolution or relay setup. On rejection by these checks, the server attempts its existing failure response and closes the control connection. This is separate from the reserved-byte and fragment checks on UDP datagrams.

Worker construction completes the native session class hierarchy before the proxy starts worker threads. Session creation then uses complete class descriptors, including their TCP and UDP interfaces and server-specific bind callbacks.

Cancellation remains terminal throughout initial greeting, authentication, request parsing, address resolution, binding and response transmission. Setup does not replace an already terminal state with a fresh configured timeout. The shared I/O yielder checks terminal state before and after suspension and records an expired wait as terminal. Setup rechecks that state after operations which may suspend, before creating further relay sockets or issuing the next protocol response. A successful underlying I/O or DNS return cannot turn a canceled setup into a successful association. Authentication-method, username/password and connection responses succeed only after their exact encoded length has been sent. A positive partial write is an incomplete setup response, so the caller stops before the next handshake or relay stage and releases the session-owned sockets. Bytes already transmitted cannot be recalled, and an outstanding DNS operation still has to return before its lookup-owned state can be released.

### Complete message and frame handling

Standard UDP input validates minimum length, address form and length, reserved bytes, unsupported fragmentation and actual truncation flags. Nonzero RSV or FRAG input is discarded before peer learning. A malformed or truncated prefix is not forwarded as a normal complete payload. Empty payload datagrams remain messages and are distinct from an empty receive queue or TCP EOF.

UDP-over-TCP uses its own frame-length interpretation. The standard zero-RSV/FRAG rule is not applied to the frame's length field. Headers and bodies must be fully read before a message is reported complete. An empty NAME or a NUL within a complete declared NAME is a terminal frame error, and the invalid message is not published to the caller. Successful messages preceding a later receive failure retain their completed count at the receive API. If that failure also terminates the association, the relay stops before resolving or forwarding the received prefix. A partially written stream frame is not reported as a successfully sent datagram, and a new frame is not appended as though the incomplete frame had succeeded.

DNS lookups for domain destinations use the configured address family. The existing numeric IPv4/IPv6 fast paths retain their literal-address behavior. Forwarding compacts successfully resolved destinations, keeps empty payloads and continues after individual destination or send failures. Successful send prefixes advance the message index; a zero-progress or ordinary failed send skips that message without retrying an unbounded loop. Cancellation, control-connection closure, an expired wait or association setup failure remains terminal, including when a native helper returns a positive completed prefix. UDP I/O and buffer-maintenance waits check terminal state before and after suspension so waking a task cannot resume a canceled transfer. Destination resolution and the one-time outgoing bind recheck cancellation and control closure after returning. Failed binding marks the association terminal. The outer relay then stops before receiving or allocating for its other direction, and an already canceled association does not allocate relay buffers.

Reply forwarding discards an ordinary failed client-facing UDP datagram, including an `EMSGSIZE` after SOCKS encapsulation, while preserving successful prefixes and continuing with the remaining queued replies and later replies on the same association. Explicit cancellation and incomplete UDP-over-TCP sends remain terminal.

### Adaptive buffer policy

Each managed receive slot starts with a 1,500-byte data region. Capacity demands are rounded up in 500-byte steps. Darwin and Linux obtain an exact next-datagram size before allocating: a requirement of 48,001 bytes obtains 48,500 bytes; 30,001 obtains 30,500. On other platforms the non-consuming probe grows geometrically until it can observe the complete datagram. Starting at 1,500 bytes, a 48,001-byte datagram can therefore leave 96,000 bytes allocated until cleanup, while recording the same 48,500-byte demand bucket. The required size includes any protocol header stored in the same receive region. Allocation does not impose a separate arbitrary 65,536-byte ceiling, but wire-format, arithmetic, allocator, socket and network-path limits still apply.

Each 500-byte demand bucket records one expiry time based on a 300-second holding interval. A demand refreshes its own bucket, not every smaller or larger capacity. Small messages therefore do not keep a large buffer alive indefinitely. Cleanup checks the recent demands at a 60-second cadence and returns unused expanded storage toward the largest still-needed bucket or the 1,500-byte base.

For example, a large demand followed two minutes later by a smaller expanded demand permits the first capacity to expire independently. Cleanup needs no subsequent application packet to run. It never moves storage still referenced by active I/O, and it does not treat maintenance activity as new client traffic that extends the communication timeout.

The constants are `UDP_BUF_SIZE`, `UDP_BUFFER_GROW_STEP`, `UDP_BUFFER_HOLD_SECONDS` and `UDP_BUFFER_CLEANUP_SECONDS`. An expanded slot of capacity C holds `(C - 1500) / 500` expiry entries, each a `uint64_t`, followed by its contiguous replacement data region in the same allocation. Resizing copies the relevant expiry entries, not stale packet content. The original base storage remains available and is reused when expanded storage is released.

## Implementation and ownership

The Swift application sources remain the upstream versions. The feature's existing `Socks5/Info.plist` and project settings also declare a single application scene and a local-network usage description. One scene keeps the interface aligned with the process-wide native server, and the description explains access by devices on the hotspot or local network. These application configuration declarations are separate from UDP framing, peer checks and buffer management.

The feature applies seven ordered patches from `Build/features.json`. Each path inside a patch is relative to its declared application root.

| Patch | Application root | Responsibility |
| --- | --- | --- |
| `hev-udp-port-zero.patch` | `.` | Relay setup for an unknown client port. |
| `hev-udp-sockaddr.patch` | `src/core` | Complete native address conversion and reply address reporting. |
| `hev-udp-peer-filter.patch` | `src/core` | Source identity before peer learning and for each queued datagram. |
| `hev-udp-dynamic-buffer.patch` | `src/core` | Managed buffer capacity and retention, complete framing, relay progress and Darwin send repair. |
| `hev-netaddr-result.patch` | `.` | Task-appropriate DNS execution, result interpretation, reply lifetime and shared aide initialization. |
| `hev-udp-domain.patch` | `src/core` | Bounded, nonempty NAME construction and validation before I/O, peer learning, frame completion and lookup. |
| `hev-session-setup.patch` | `.` | Session class initialization, request/reply handling, terminal setup, worker authentication ownership, signal reload lifetime and pool/resource failures, including shared atomic reference destruction. |

Empty-payload acceptance and destination-error progress belong to the upstream core; the custom patches retain the stronger validation, adaptive capacity, peer policy and Darwin send correction. The public message representation remains address, contiguous buffer and length. The existing association owns the sockets; its native task owns buffer lifetime and cleanup scheduling.

The address-result patch owns the shared helper used by listener setup and outgoing UDP binding. After task-system initialization, serial startup uses ordinary libc resolution when no task is running; session tasks retain the asynchronous task resolver. This avoids a scheduler-yield busy loop during startup DNS without blocking other running session tasks. Every nonzero DNS status is an error, including platforms with positive error values. Failed resolution returns before accessing result storage, while successful IPv4 and IPv6 conversion remains unchanged. The DNS aide callback consumes the proxy's single outstanding request and performs no proxy, call or descriptor access after publishing its reply. A following request produces the next read-readiness event. Interrupted request/reply reads and writes retry without treating EINTR as transferred data or releasing the borrowed call; EAGAIN retains the existing wait. The existing aide initialization mutex publishes the shared reactor only after its thread starts successfully; another worker can retry initialization after a creation failure. The domain patch shares one private bounded-name predicate between complete-message validation and address conversion. It scans only the declared name bytes after the receive path has established their availability.

The session-setup patch keeps one setup invariant across the shared handshake and I/O yielder, the server-specific bind callbacks and worker construction. Its root-relative paths include the server repository, its pinned core and the shared atomic reference implementation in the task system. Existing functions retain those responsibilities; the patch adds no separate session coordinator, worker thread or per-session synchronization object.

Authentication publication keeps the current authenticator on its worker thread and transfers one owned reference through a typed atomic pending slot. Initial authentication is installed before either worker task can accept a connection. Replacement releases a superseded pending object, while existing sessions retain their own reference. Worker cleanup after its tasks and thread stop releases both remaining slots exactly once. Shared atomic reference decrements use acquire/release ordering before the last owner destroys an object.

The library-installed SIGUSR1 handler retains the published main worker with lock-free atomic lifetime accounting, records a pending reload and sends a coalesced byte through that worker's existing nonblocking event endpoint. Its notification never enters the normal sender gate, so a signal can interrupt that gate's owner safely. Worker zero's ordinary event task performs authentication loading through an optional internal callback before consuming its pending authenticator. Finalization first unpublishes the worker and drains in-flight handlers. It then joins the workers and finalizes every task system before restoring the complete previous SIGUSR1 and SIGPIPE dispositions. The detached handler remains safe while cleanup runs. Partial signal setup follows the same cleanup path. The separate weak CLI entry point's SIGINT installation is outside this library-entry signal contract. The native Makefile explicitly disables the optional process-wide SIGBUS/SIGSEGV diagnostic handler (`ENABLE_STACK_OVERFLOW_DETECTOR=0`), whose per-thread saved actions do not have process-wide ownership. Independent stack overflow protection (`ENABLE_STACK_OVERFLOW_DETECTION=1`) and the selected mmap guard page remain enabled.

Socket and task-event registration must succeed before dependent I/O begins. The socket factory closes only the descriptor it created if both registration attempts fail. Server and TCP/UDP splicer entry points preserve caller-owned descriptors on failure; the session owner releases them. The UDP splicer validates its counts and registers both descriptors before allocating relay buffers; a registration failure therefore allocates no relay storage. The server service propagates the splicer result. A worker task-system initialization failure or task-loop exit stops the whole pool before its threads are joined, including siblings that have not started their task loop yet. Internal sibling shutdown reuses the serialized Stop implementation without recording a new pending Stop after the current invocation's send gate has closed. Public Stop retains its pre-start intent semantics. A failed listener registration stops its worker through the existing event channel. A failed event-channel registration or an incomplete event read enters the existing stop path, so the accept task does not remain asleep without a registered wakeup source. Terminal event-task exit clears the channel send state before returning, so the later proxy Stop does not write to an ended receiver. Stop and Reload notifications retry a no-transfer interrupted write while retaining the existing sender gate and coalesced event bit; event-read failure keeps its terminal pool-stop behavior.

The worker checks its run state before each accept iteration. An ordinary accept error or a session/task allocation failure waits on the existing task timer for 10 milliseconds before retrying. Other sessions can then process their pending I/O and release resources; Stop can wake this wait. Successful admissions add no new wait, allocation or thread. The delay bounds an otherwise immediate resource-failure retry loop when no earlier wakeup occurs; it is not an admission or shutdown deadline under scheduler or process suspension.

`UDPBuffers` owns the relay slots and the cleanup/idle deadlines, while each `UDPBuffer` describes one slot. Automatic growth belongs to this managed forwarder path. The public `hev_socks5_udp_recvmmsg()` entry retains caller-owned storage and does not resize an arbitrary caller buffer; capacity and truncation checks still prevent an undersized caller buffer from becoming a successful complete frame.

The relay's `UDPWorkspace` holds reusable message, iovec, packet, socket-address and wire-prefix arrays in the same allocation as the slot metadata. Its single owner finishes one receive or send before reusing those views; an I/O suspension keeps the storage alive. Packed reply addresses remain separate from native socket addresses during conversion. Every typed span includes checked size arithmetic and alignment. Configured batch counts therefore do not create count-sized arrays on the task stack, and the signed base-buffer offset calculation is no longer needed. The relay still makes two initial allocations and does not allocate descriptor arrays for individual packets.

UDP-over-TCP validates the complete requested batch before its first write, then writes at most ten frames per native helper call. That helper copies iovecs onto the task stack, so limiting each call also keeps its stack use and the operating system's iovec count bounded. A configured batch larger than ten remains a complete batch: subsequent writes send its remaining frames. The default ten-frame batch still needs one helper call. Cancellation is checked before each following chunk, and an incomplete chunk ends the stream instead of allowing a later frame to follow it. The public send/receive signatures remain unchanged; a zero count is an allocation-free no-op, while an unrepresentable count or an already terminal association is rejected before allocation. Direct caller-owned TCP receives retain their allocation-free path; other direct public calls release their temporary descriptor workspace before returning.

Socket-datagram receive sizing occurs before consuming that datagram. Darwin uses `SO_NREAD` and a one-byte non-consuming probe when a zero result could mean either an empty datagram or an empty queue. Linux uses `MSG_PEEK | MSG_TRUNC | MSG_DONTWAIT` with a zero-length receive buffer. Actual receive length, flags and capacity are checked again when the message is consumed. Different queued datagrams are sized individually rather than assuming that a batch has the first message's size. An allocation or size-overflow failure during either the probe or the shared reserve step leaves the queued datagram unconsumed and ends the association. An ordinary interrupted or temporarily empty query retains the active timeout. A completed prefix remains a receive-API result, while the terminal relay barrier prevents further forwarding or work in the other direction.

UDP-over-TCP has a different consumption boundary: the receiver first reads the five-byte framing prefix to determine and validate the address and payload lengths. A managed slot then reserves space for the address and payload before the remaining bytes are read. If that reservation fails, the prefix is already consumed; the timeout is set to zero and the incomplete frame is not reported as a successful message. Any fully completed messages earlier in the same receive call retain their completed count. This is fail-closed stream handling, not a claim that TCP can put consumed bytes back into its receive queue.

Expansion allocates the required rounded space directly when an exact size is available. The portable probe retains its checked geometric growth rather than immediately shrinking and copying after every probe. Bucket metadata records capacity demand rather than a per-packet history. Allocation failures do not leave dangling buffer references. A failed shrink retains usable storage for a subsequent cleanup attempt. Association teardown releases its owned expanded storage independently of the holding interval.

The task's existing timer supports cleanup and communication timeout without a new production thread, Swift timer or global buffer registry. When no expanded capacity remains, unnecessary cleanup wakeups stop. Communication timeout follows the task timer's clock, excluding system sleep where supported; buffer retention uses its separate elapsed-time clock, and the next wait compares remaining durations rather than unlike absolute clock readings.

On Darwin, a valid large send rejected with EMSGSIZE may require a larger socket send-buffer allowance. Only that failure path queries `SO_SNDBUF` and requests a larger allowance when it is actually too small. The same unsent message index receives at most one adjustment-and-retry opportunity; after successful progress, a different unsent message in that batch can receive its own opportunity. Completed messages are never resubmitted by this retry path. Socket allowance is distinct from user-space payload retention and may persist for the socket's lifetime.

## Design rationale and resource cost

Contiguous messages preserve the engine's existing parsers, send interfaces and ownership model. Exact-size rounded growth avoids repeated reallocations through intermediate sizes on Darwin and Linux; the portable probe trades extra retained capacity and possible intermediate allocations for a complete non-consuming observation. Keeping recently useful space avoids allocating and freeing large buffers for each packet. Expiry per capacity bucket provides bounded metadata per supported capacity range without recording every message timestamp.

The implementation has real costs: next-datagram sizing calls, some loss of Linux receive-batching benefit, bucket metadata, expanded capacity and temporary old/new storage during resizing (growth or shrink). The existing base storage can coexist with an expanded region. Memory returned to an allocator need not immediately reduce process RSS. These costs are different from continuously allocating a maximum-size buffer for every small message.

Reusable descriptors move count-dependent storage from the task stack to the connection's heap allocation. For the measured 64-bit Linux layout, the default ten slots in each direction use 30,000 bytes of base payload, 640 bytes of slot metadata and 1,860 bytes of workspace, totaling 32,500 bytes before expanded storage and other session costs. Other platforms derive their layout from `sizeof` and alignment. This modest persistent cost avoids per-batch allocation in the relay and permits larger configured batches without enlarging the task stack. The three-byte send prefix also avoids reserving a full maximum-length address structure for each prefix.

Wire NAME validation scans at most the protocol's 255 declared name bytes; C-string construction examines at most 256 bytes to detect an excessive length. These checks allocate no storage or copied name history. CONNECT reply reporting adds one socket query after successful connection. Session class preloading adds an existing cached class lookup during serial worker construction. Terminal checks reuse the association's existing timeout state. Keeping these checks in the existing conversion and setup functions avoids additional public interfaces and ownership objects. Authentication retains the existing pointer storage and atomic operations, with explicit ownership and stronger reference-decrement ordering. DNS callback completion needs no new synchronization object; the existing initialization mutex is used when a task DNS proxy is created, not for each lookup or packet. Signal reload reuses the existing event task, descriptor pair and coalesced event bit. Its optional callback adds one pointer per worker, measured as eight bytes on the verified x86_64 layout; saved dispositions and atomic publication state have fixed process-level storage. Notification and lifetime accounting execute only for signals and server setup/teardown. Disabling the optional diagnostic handler also removes its per-worker allocation and alternate signal stack setup; it adds no replacement signal manager.

The fixed-port/unknown-peer policy is not silently changed to reduce association ambiguity. Multiple unknown clients sharing one fixed relay endpoint can be associated with the wrong control connection. A forced dynamic-port fallback would change the configured behavior and network reachability requirements; it is not part of this implementation.

## Verification contract

`Tests/udp_compat_audit.py` executes real native networking and separate controlled-boundary fixtures. Source, native patch order, formatting and exact patch reversal are checked independently from behavior. The address fixture covers port values, normalized addresses, canaries and IPv6 preservation. It also checks complete and truncated NAME addresses, empty names, NUL at different positions, validation before learning an unknown peer, established peers and unchanged output from rejected direct conversions. A separate native-address fixture checks serial and running-task resolver routes, positive and negative DNS errors without a result, unchanged failure output, and successful IPv4/IPv6 results. `Tests/udp_address_conversion.c` checks the shared destination converter with controlled resolver scopes, direct and length-prefixed names, scoped-to-unscoped output reuse, numeric IPv4/IPv6 forms, port preservation and surrounding canaries. Each reused-output case seeds the preceding scope immediately before conversion, including numeric and IPv4 NAME conversions, so a missing scope clear cannot be masked by an earlier successful DNS result. Empty NAME values, names containing a NUL byte and unknown address types are rejected without changing the output. Constructor checks cover lengths 1 and 255, empty and excessive names, an unterminated 256-byte input, output canaries and rejection before client allocation. Peer tests cover foreign first senders, wrong ports, queued packets and continued progress after rejected batches.

The buffer fixtures exercise demand rounding, expiry, large-to-small retention, overflow and allocation failure, queue/zero-length distinctions, truncation, partial success, cancellation and final cleanup. Query fault controls distinguish terminal ENOMEM/EOVERFLOW from EAGAIN/EINTR while preserving queued data and existing buffer history. A reference history calculation checks the bucket policy rather than assuming the implementation's own result is correct. The full-splicer fixture exercises initial and expanded allocation failures, terminal setup, queued replies, cancellation and complete heap cleanup using the actual relay loop, sockets and task scheduler. It also verifies that socket ownership stays with the association and that control closure during destination conversion or binding prevents outgoing traffic and leaves queued replies untouched. The live-hold and timer fixtures use actual sockets, clock, allocator and Hev scheduling; their test-only communication timeout is distinct from the application's configured timeout.

Workspace checks cover aligned non-overlapping spans, count and allocation-size overflow, allocation failure without publishing partial views, zero-count calls and terminal entries. The full-splicer lifetime cases run with both two and one hundred slots per direction. The network suite also runs with 342 configured slots and the default native task stack, exercising UDP and UDP-over-TCP with empty, small, large and mixed payloads. Stream checks cover the ten-frame write boundary, larger multi-chunk batches, failure and cancellation after a successful chunk, and invalid trailing frames rejected before any write.

The stream-boundary fixture checks complete frames, every tested truncation point, address/header consistency, partial sends and wire-length rejection in sanitizer and optimized configurations. NAME cases cover managed and caller-owned buffers, an earlier successful frame, empty-name/NUL rejection and the terminal barrier before resolution or forwarding. It also exercises both actual forwarding loops with compacted destinations, empty payloads, successful prefixes, zero-progress errors and cancellation before or after progress, retaining the composed meter send path when present. Every tested partial backward TCP write remains terminal. The network suite compares full payload content and address, including payloads above the base capacity, and checks that an oversized encapsulated reply does not stop queued or later replies on the same association. Negative controls prove that missing peer, address, length or completion checks are detected. Observational fixed-unknown failures remain explicitly separate from required supported profiles.

The send fixture checks both repeated failure at one unsent index and a new repair opportunity after progress advances to another index. The session-setup fixture, `Tests/udp_session_setup.c`, checks worker-owned class initialization before parallel interface readers. It compares successful and canceled setup at the initial greeting wait, request NAME lookup, relay listen-address lookup, public reply-address lookup and outgoing TCP bind-address lookup. A separate already-canceled entry case checks that handshake setup does not reset terminal state or issue authentication traffic. The resolver API is controlled while actual Hev tasks suspend and resume; sockets, binding and connecting use the native operations. The fixture checks the absence of post-cancellation socket creation, binding, connecting and successful responses, along with descriptor cleanup. It also checks generic yield/wait cancellation with finite and infinite timeouts and expiry of a finite wait. Controlled send completions require both two-byte authentication responses and IPv4/IPv6 connection responses to reject every shorter completion, zero progress and errors while accepting the complete response. CONNECT checks require its actual local endpoint, failure on an unsuccessful endpoint query, and preservation of destination attribution in a metered composition. The real network fixture compares the BND reply to the destination listener's accepted peer, then exchanges full payloads in both directions, across both control/destination families, literal/NAME requests and one/four workers. It also proves that an empty-NAME datagram cannot claim an unknown client port.

Resource-failure fixtures exercise the actual socket factory, server, splicers and worker code with controlled task-API and allocation outcomes. They check fallback registration, rejection before I/O, descriptor ownership, buffer cleanup, startup failure, Stop and recovery scheduling. The worker fixture also injects one no-transfer EINTR separately into Stop and Reload writes, requiring a retried write, receipt of the actual event, and cleared sender/event state. The proxy lifecycle fixture executes the full native main/finalization path with one, two and four workers. It covers normal shutdown, worker-zero and sibling Stop, sibling task-system/event/listener registration failures, event EOF and a delayed sibling exit after the send gate closes. Each case requires real descriptor closure, all joins, return and no unintended Stop carried into the next invocation. Authentication cases cover eight replacements with retained sessions, initial authentication before acceptance, pre-start Stop and sibling initialization failure, with exact object allocation/free counts. A separate `--auth-publication` mode uses ordinary pthread stacks and the real publication/load functions; the Darwin audit instruments both that mode and the atomic reference implementation with ThreadSanitizer. This ordering check is separate from the default real task/event lifecycle matrix. A separate real-server test enforces and reads back only the child process descriptor limit before exec, retains client sockets from more successful connect calls than that limit, and requires an established UDP association to keep forwarding, new admissions to recover after pressure is released, and Stop to finish while pressure remains. On Linux, the old server is an explicit starvation control: it must remain alive before Stop, time out after Stop and require watchdog termination, so a crash cannot satisfy the control. These are native host checks; they do not establish physical iOS resource limits. TCP setup tests require zero-RSV success, nonzero-RSV failure and closure, and successful new associations after rejection.

`Tests/udp_dns_lifecycle.c` executes the actual task DNS proxy and aide reactor. It checks competing first callers after thread-creation failure, repeated successful and failed getaddrinfo/getnameinfo calls, owner destruction after the reply, and a second request queued before the first callback returns. Four no-transfer EINTR results are injected at the request/reply syscall boundaries; they are controlled API outcomes, not a claim of device-observed interruption. The existing cancellation fixtures also run with this DNS implementation.

`Tests/udp_signal_lifecycle.c` uses actual POSIX signal delivery with the native proxy, worker and library entry points. It checks reloads, mixed and coalesced notifications, interrupted sender ownership, prior handler/flags/mask restoration, unchanged host SIGBUS/SIGSEGV dispositions during execution and after cleanup, restoration after task-system finalization, errno preservation, setup failures, in-flight handler teardown and recovery. Optimized and address/undefined sanitizer executions are separate from the pthread-only authentication ordering mode.

The feature's SDK checks compile the actual C files named by its patches and applicable Swift source for the configured target. They do not constitute a new device installation or an IPA produced by a native-only audit route. The documentation checker validates inherited prose without changing any of these functional test inputs or oracles.

## Operation and limitations

Use a clean full-history checkout and `python3 Tests/udp_compat_audit.py` for the standalone audit. Feature manifests identify the source roots and patch order. The application's server configuration accepts UDP port zero, but its default and configured fixed-port behavior are not automatically migrated. A client must use the relay endpoint returned by its association response.

The application does not override the native `udp-copy-buffer-nums` setting, whose default is ten. A native administrator may configure a larger positive count; the workspace retains that count subject to representable sizes and available memory. Nonpositive counts do not enter the relay. Arbitrary task-stack reductions and unlimited memory availability are not implied by the removal of count-dependent stack arrays.

Each association binds its destination-side UDP socket once, using its first destination's family. Family-specific binding may prevent later traffic to the other family; Linux IPv4-first with `0.0.0.0` is one such case. Mixed-family audit profiles leave both outgoing bind addresses empty. Default bindings and larger buffers do not guarantee mixed-family forwarding within one association.

Correct independent shutdown of multiple unknown-peer associations on a single fixed UDP endpoint is an explicit limitation. Peer checks are not cryptographic authentication, and a valid first sender sharing the expected IP can still compete to establish an unknown source port. NAT, firewall and socket/path limits are not overridden by a larger buffer.

The configured minimum is iOS 17.2 and the primary target is physical iOS 27 through SideStore standalone or LiveContainer guest execution. Actual installer, host, VPN/hotspot, suspension, long-background and device-resource behavior require separate evidence. Timer intervals are scheduling policies, not deadlines that override blocked I/O or process suspension. An outstanding native DNS request must return before its caller can release lookup-owned state; cancellation and control closure prevent further relay work when that request returns.
