# Integrated SOCKS5 application

## Purpose and scope

Version 3.0.0, build 1 combines UDP compatibility, peer socket I/O statistics, server control, settings persistence, background services and the approved application icon. The release composes each feature's exact owned implementation through one application root.

Feature documents define each module's behavior and tests. This guide defines their interaction and the release's product-validation boundary. Source, parent, workflow and package references identify the same declared composition.

## Functional behavior

### Four-tab application

The tabs are Statistics, Server, Background and Settings. One SettingsStore owns durable configuration. One ServerController owns native server execution. One BackgroundKeepAlive holds the root's independent audio and location intent and registers with the process-level LoopAudioService. Changing the selected tab does not recreate those service owners.

An explicit audio choice reaches the audio service before the settings store accepts its memory value and queues its asynchronous save. Repeated On or Off choices are preserved even when their Boolean value is unchanged; a rapid Off-On pair reaches the service in that order. Server Stop similarly requests live shutdown before saving intent, including during initial loading or a load failure. Location Off also reaches the controller immediately; Location On retains the existing loaded-settings and permission flow. Start uses the loaded configuration when ready; a Start received earlier is retained and applied after loading merges the explicit edit with the saved fields. A storage failure remains visible while live intent takes effect, although durable intent can remain different until writing succeeds. If the store cannot allocate another intent revision, On and Start expose its terminal error before starting service work; Off and Stop still reach their service first and retain false in memory without reusing an identifier.

Automatic restoration waits for the store's ready state. Its nonpersistent change identity retains the accepted revision and user, load or import origin; the root compares the complete identity rather than a revision number alone. Three fixed service-intent stamps reuse that identity for audio, location and server running. They preserve an accepted Off or Stop across unrelated setting edits while rejecting an older continuation after a newer choice for the same service, including an identical choice. Whole-snapshot load and import update all three stamps. A stored user change returns through the non-explicit synchronization path, so its echo, a tab change or a server edit does not manufacture another explicit audio recovery request. Loading and validated import use that same synchronization path. If a service publication synchronously accepts a newer input, the root also stops applying the rest of an obsolete settings snapshot.

A successful import can change running intent, Background choices and selected tab together; the server controller validates and serializes any replacement, while audio and location keep their own independent gates. The eleven server-configuration controls and Start remain disabled during the owned invocation, even though an import can request a replacement through the root. Stop has its own enabled condition: it remains available while either the controller owns an invocation or the current settings snapshot requests running, including while shutdown is in progress. Disabling configuration editing does not disable Stop.

Statistics counts successful socket work at both client and destination boundaries, by worker and normalized peer IP. In means bytes accepted by the OS for this program's writes to that IP; Out means bytes consumed by reads from that IP. Total sums those endpoint observations, so relaying 1,000 bytes from A to B contributes 1,000 A.Out and 1,000 B.In, before protocol bytes. Unresolved peer addresses use Unattributed. Stop/Start preserves process volume; a new process starts fresh. Total/IP volumes and rates refresh together immediately on entry, then target the next device-clock `.0`/`.5` second boundary for each sampling start, only while Statistics is visible and the scene active. Each completed sample selects the next future boundary, skipping missed boundaries; exact execution times are not guaranteed. Rates use actual elapsed uptime, never wall-clock differences or a fixed 0.5-second divisor. Hiding or inactivation cancels sampling and skips row sorting and table formatting; a native read already in progress is not interrupted. Native accounting continues, and returning establishes a fresh zero-rate baseline. Peer addresses are decoded only for new visible sampler entries; existing labels reuse the same entry lookup. Statistics owns neither server lifetime nor durable configuration. Background audio/location can remain enabled while the server is stopped.

### Native and resource behavior

The release composes the seven UDP compatibility patches, three statistics patches and ServerControl startup/stop changes once in their declared order. It retains complete datagrams, strict peer/header/frame handling, the 1,500-byte base with 500-byte demand buckets, 300-second demand retention and 60-second cleanup checks. Darwin/Linux use exact-size allocation; the portable geometric probe can retain extra capacity until cleanup. Allocation or overflow failures in either sizing or reservation terminate the relay while preserving its queued datagram. Length-prefixed NAME destinations must be nonempty and preserve their complete identity before peer learning or frame completion; shared C-string construction rejects excessive lengths before changing output or allocating a client. CONNECT replies report the actual outgoing local endpoint after destination attribution is established. Serial startup DNS uses libc while running tasks retain their asynchronous resolver. DNS callbacks finish all proxy access before publishing a reply, and the existing initializer mutex prevents use of a reactor whose thread creation later fails. Interrupted request/reply operations retry while retaining their borrowed call state. Worker construction completes native session classes before worker threads start, and terminal setup state survives resumed I/O and address lookup. Resolved IPv6 destination scope survives shared address conversion, and unscoped destinations clear a stale output scope. Scoped NAME text uses the existing complete resolver path on Darwin as well as Linux. Initial authentication and connection responses require every encoded byte; an incomplete response terminates setup while its already accepted bytes remain accounted. Counter lifetime and IP attribution are independent of temporary buffer lifetime.

Socket and task-event registration must succeed before dependent I/O; failed UDP registration allocates no relay storage. Failed accept or session/task allocation attempts yield through the existing task timer, while successful admissions keep their normal path. A failure or exit in any worker stops the whole pool before joining it. Internal sibling shutdown and meter-entry failures do not carry a pending Stop into the next invocation, including when reported after the current send gate closes. A terminal event receiver clears its send state before later proxy Stop. Authentication uses worker-owned current state and an atomic pending reference, installs the initial value before accepting, and releases superseded or retained objects exactly once. Shared last-unref ordering precedes destruction. Library SIGUSR1 reloads use the first worker's existing event task and coalesced channel; the handler performs only lock-free state changes and a nonblocking notification. Shutdown unpublishes the worker and drains in-flight handlers before freeing it, joins every worker and finalizes the task systems, then restores the complete prior SIGUSR1 and SIGPIPE dispositions. Stack guard pages remain enabled while the optional per-thread diagnostic handler is disabled, preserving the host SIGBUS/SIGSEGV dispositions. The same inherited checks exercise these paths in the combined engine without changing meter ownership or server intent.

The fixed UDP port default and multiple-unknown-peer limitation remain. Socket accounting includes SOCKS negotiation, authentication, replies, UDP encapsulation, framing, consumed rejected input and successful prefixes before failure. It excludes peeks, unread or unaccepted bytes, internal copies, OS-generated headers, ACKs and kernel retransmissions. It does not measure remote delivery, interface traffic or billed data. Background retains its 0.5-second health/retry policy and original looping silent WAV; the icon remains a static catalog.

## Implementation and ownership

`AppRoot` owns the three StateObjects and binds the four tabs to the selected-tab setting. JSON is the sole durable settings owner in release; the standalone Background AppStorage path is not duplicated in the integrated root. `ServerSettings` and `ServerController` do not depend on the settings store. Background does not read JSON or call the native server. Statistics and icon resources do not introduce reverse dependencies into those services.

Background owns LoopAudioService, PlaybackProgressMonitor and RecoveryExecutionLease. Their addition changes the actual application Swift source count from twelve to fifteen; the existing target inputs, build settings and original silent WAV remain intact. The audio control lane owns bounded scheduling and policy state, while its separate serial I/O lane exclusively owns AV objects. One outstanding audio operation retains its real lifetime through Off, expiration or a delayed callback. A finite execution claim protects a transition and does not turn a blocked system call into a canceled operation. Settings has its own serial storage lane with one running and one latest pending save; audio never waits for that storage lane.

`Build/features.json` declares native inputs and patch order. `docs/feature-membership.json` preserves the functional file mappings and exact composition exceptions. `docs/documentation.json` owns current-parent document copies and the permitted documentation-validation changes. Each declared feature revision and the shared main remain in actual Git ancestry; content maps do not substitute for that relationship.

The native order is `hev-udp-port-zero.patch`, `hev-udp-sockaddr.patch`, `hev-udp-peer-filter.patch`, `hev-udp-dynamic-buffer.patch`, `hev-netaddr-result.patch`, `hev-udp-domain.patch`, `hev-session-setup.patch`, `hev-socket-meter-task.patch`, `hev-socket-meter-core.patch`, `hev-socket-meter-server.patch` and `hev-server-startup-stop.patch`. Product builds link the generated feature framework in a disposable source copy; the shared tracked XCFramework remains the unpatched baseline.

UDP owns bounded nonempty NAME construction/validation, DNS execution and reply lifetime, session setup, authentication publication, library signal reload lifetime and pool-failure checks. Root-relative patches include the pinned core and task-system DNS/atomic-reference implementations where those lifetimes are enforced. ServerControl retains its canonical startup/Stop patch bytes and runtime behavior. `Build/server_patch.py` owns the Release-only context projection for the startup authentication check: exactly three context lines match the newer UDP signal setup while every added/removed line and patch header remains identical. `Build/server-patch-context.json` binds the canonical and derived patch hashes and all five affected source files' pre/post SHA-256, Git blob IDs and modes. The build uses ordinary `git apply --check` and `git apply`, verifies the complete affected output, and uses the same derived bytes for reverse checks. Unknown patch bytes or native input states are rejected. Composition adds no second session coordinator.

Statistics owns all three meter patches: socket-result observation in `third-part/hev-task-system`, worker/IP storage and peer adapters in `src/core`, and worker binding plus the public snapshot API in the server repository. `worker_meter.c` owns registration, counters, publication and reading; `hev-socks5-meter.c` connects the storage to socket observations. Existing proxy worker boundaries call the Statistics binding. Neither meter module starts or stops the server. The proxy owns startup-failure cleanup when worker storage cannot be acquired, using its internal current-invocation Stop path; ServerControl owns application running intent and normal start/stop policy. The same meter patches apply to standalone Statistics and integrated Release, with no Release-specific meter implementation or OS-specific counter.

Each worker updates private 64-bit counters and publishes C11 32-bit atomic words. Readers use sequence/epoch checks and retry until each worker part is coherent, then merge by IP and Total. Ordinary I/O updates have no global counter lock or shared Total update; identity registration and worker reuse still coordinate shared metadata. Separate Total and row calls are not one simultaneous instant. The endpoint API copies packed rows into caller-owned memory; stable IDs are independent of row positions.

The UI test target combines integrated behavior, Background audio and the exact Statistics traffic test. Temporary test code is excluded from the application target; class names prevent test symbol collisions without changing assertions. Each audio case establishes verified Off intent through normal UI setup and XCTest teardown, preserving intent during its relaunch scenarios. Exact Playing predicates use a 10-second wait after element lookup; Off checks retain their 5-second waits. The harness attempts result and attachment export even when xcodebuild fails and preserves that failure.

## Design rationale and resource cost

Composition through one root makes ownership visible and prevents service lifetime from following tab visibility. Keeping persistence, server intent, background recovery and measurement separate avoids duplicated sources of truth. Exact feature mappings allow the release to reuse implementation rather than maintain parallel copies with different behavior.

Integration adds no separate runtime management layer. Costs remain in datagram sizing, bounded NAME scans, adaptive buffers, process-lived IP/worker entries, counter publication, visible snapshot/sort work, server/AudioSession operations and audio/location scheduling. Session initialization uses the existing cached class lookup during serial worker construction, and terminal checks reuse existing association state. Authentication adds no pointer storage and strengthens the existing atomic reference decrement. DNS uses the existing initialization mutex when creating a task DNS proxy and adds no per-packet lock. Signal reload adds one optional internal callback pointer per worker and fixed process-level atomic/disposition storage, reusing the existing task and descriptor pair. Signal accounting is outside packet processing. Reader retries are not bounded, although writers do not wait for readers. Buffer release need not immediately reduce RSS. No universal CPU/RAM minimum or physical battery improvement is asserted.

Root synchronization retains one last-applied change identity. It adds no timer, per-event history or second audio owner. The audio service retains the original 0.5-second health/retry policy and one bounded scheduler; progress corroboration uses limited additional samples and does not equate a moving clock with verified physical output. Speculative recovery remains disabled without the required environment-specific false-positive acceptance. Normal playback reuses its player and original WAV data instead of allocating a periodic replacement.

Source and artifact checks are build-time work. They verify that the product links the declared feature engine and carries correct resources, not that every operating-system or network condition is supported.

## Verification contract

The combined native dispatcher exercises the declared eleven-patch engine, not a collection of unrelated feature badges. The statistics executable UDP prerequisite must equal its declared current UDP parent, and release requires the same parent revisions for executable verification and inherited prose. The complete Statistics implementation and test tree are retained by exact file content, mode and staged index. Its original workflow files are retained verbatim in `Build/inherited-workflows/`; these reference copies are not registered as additional GitHub workflows and do not launch duplicate feature jobs. Linux explicitly builds buffered and splice modes; Apple exercises buffered Darwin behavior. Tests require exact successful TCP/UDP socket accounting, full payload integrity, both peer roles, independent communication timeout and safe adaptive-buffer reclamation.

The Statistics-owned fixtures cover partial I/O, failure, cancellation, peeks, message prefixes, accept/reset, worker reuse, packed rows and both peer directions. The parent stream-boundary, splicer-lifetime, resolver-result and session-setup fixtures execute on both the statistics ten-patch engine and the release eleven-patch engine. They require terminal relay failures to stop before further work, release all owned buffers, and reject every nonzero resolver result, including positive Darwin errors. A source-inheritance regression runs in the exact statistics-owner worktree so missing test files, stale prerequisite references and an omitted composed execution cannot pass merely because runtime patches are unchanged. Datagram and stream fixtures cover truncation, headers, complete NAME identity, validation before peer learning, queue rejection, short frames and partial sends. The Darwin send fixture checks a new adjustment opportunity after progress advances to another unsent index. Session setup checks class initialization before parallel readers, already-canceled entry, successful and canceled lookup/greeting waits, actual CONNECT BND replies, timeout expiry and descriptor cleanup. Real networking compares BND with the destination's accepted peer and requires a valid sender to retain an unknown association after a competing empty-NAME packet. Full proxy cases cover sibling initialization/registration failures, event EOF, closure/join and delayed exit after finalization. Meter-entry failures are followed by fresh successful invocations with no pending internal Stop. Authentication cases retain existing sessions during replacement and count exact cleanup after pre-start Stop and sibling failures; a separate pthread-only mode checks actual publication and atomic destruction with ThreadSanitizer on Darwin. The DNS lifetime fixture checks initializer retry, repeated mixed lookups, post-reply destruction and queued readiness, including four controlled no-transfer EINTR outcomes. The signal lifetime fixture checks actual SIGUSR1 reload and sender interruption, handler/flags/mask restoration after task-system finalization, unchanged host SIGBUS/SIGSEGV dispositions, initialization failure and recovery, and cleanup while a handler is still in flight. Registry/concurrency tests check Total/IP boundaries. Swift replay checks snapshot/delta/publication, reuse of decoded peer labels, half-second scheduling targets, late execution, clock changes and actual uptime rates. Source guards preserve visibility/cancellation, and Simulator UI tests cover actual tab transitions. Timed retention checks demand-based buffer reclamation. Worker-lifetime and Stop/Start tests separately require process counters to persist.

Server and settings tests combine files, value models, the controller and actual native execution. They cover early Stop, configuration replacement, authentication, occupied ports, explicit retry, delayed completion and stale import rejection. Release passes the Statistics-owned worker baseline to ServerControl’s exact Stop-guard probe; unknown worker edits remain rejected without duplicating either owner’s implementation. Background's source-specific policy tests run in their appropriate exact-owner scope, with byte identity and separate integrated controller/async/host/UI tests connecting them to release.

`Tests/Integration/intent_boundaries.py` compiles the AppRoot routing method bodies verbatim into an isolated host. It checks direct acceptance before storage, repeated identical intent, rapid Off-On, load readiness, distinct load/import identities, echo suppression and newer input received during service publication. Its additional build uses the actual SettingsStore, LoopAudioService, progress monitor and execution lease while controlling only platform adapters and disk operations. Blocked read/write/provider cases require live Off and audio cleanup to remain independent of storage; stale or invalid imports cannot revive the service, and completed saves must match current memory. The storage host uses real Combine where available and preserves the same publisher-isolation requirement in its portable fixture. Source hashes identify every input. Guard-removal variants must compile successfully and fail at the intended behavioral assertion. These host checks do not execute AVFAudio, replace the real native listener cases or stand in for the separate Simulator UI suite.

The package checks require exact generated-framework/source identity, successful source/native/SDK prerequisites and the complete archive-to-IPA payload correspondence. Unix file types and permissions, directories, CRCs, duplicate names, icon catalog/fallbacks, original WAV, actual ARM64 target and executable/dSYM UUID must agree. Source locks, compiled products and signed installations are distinct objects.

The seeded Simulator cases cover original/remapped identity, tabs and durable Start/Stop with actual TCP responses. The three UI cases verify independent audio, server/setting behavior and known large IPv4/IPv6 volumes in the actual Total/IP tables across Stop/Start and orientation. Runtime-warning and cleanup checks remain required. Scrolling and hittability establish access, not simultaneous unoccluded display of every row.

On Simulator installation or subsequent failure, the release harness preserves the actual app bundle, Unix modes and signature diagnostics; partial timeout output remains in the original log. Before cleanup, it also records the failing device's installation-service logs and host messages matching that device UUID, each with a 15-second limit. Diagnostic failures never replace the original failure or relax the 120-second installation limit.

## Operation and limitations

Use a full-history clean checkout. The release commands are `bash Build/build.sh`, then on an Apple host `bash Build/check_swift_sdk.sh`, `python3 Build/verify_release.py`, `python3 Build/simulator_review.py`, `python3 Build/ui_review.py` and `python3 Build/record_evidence.py`. The workflow selects the applicable platform stages; an Apple-only skip on Linux is not an executed check.

Archive and Simulator builds explicitly set version 3.0.0 and build 1, and package checks read those values from the actual Info.plist. For a manual device-product build, the Apple path defaults `BUILD_IPA` to `1`; it can be set explicitly as in the release workflow. Setting `BUILD_IPA=0` skips archive generation. The following product/Simulator checks require that generated product and their source/native prerequisites; they do not build a missing archive implicitly. The delivered product is unsigned input for a signing or import process, not a device installation. Documentation edits neither alter that product nor replace its separately recorded source and hash.

Documentation verification uses `python3 Build/check_documentation.py` and the document-specific regression fixture. Add `--live-parents` to require the declared document parents to match the current remote branch tips; the default check verifies the pinned snapshot reproducibly. It preserves the frozen application, test oracles, build/workflow configuration, defaults and resources. A document-only commit is not a new runtime test or product build.

The configured minimum is iOS 17.2 and the primary physical deployment target is iOS 27. SideStore standalone signing/install/run and LiveContainer guest/shared-host execution require separate records. An unsigned IPA, changed Simulator identifier or SDK compile does not prove either physical route. Permission/file-protection states, external provider transfers, calls/Siri/Bluetooth, VPN/hotspot, suspension, long locked-device operation and device resource measurements remain separate deployment tests.

The fixed-port unknown-peer restriction, independently collected worker parts, finite counter/display precision and process-lifetime registry are explicit contracts. Persistent On is intent, not guaranteed execution or permission. Finite passing tests do not prove the absence of every possible input, allocator, scheduler or host failure.
