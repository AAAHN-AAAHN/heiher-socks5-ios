# Integrated SOCKS5 application

## Purpose and scope

Version 3.0.0, build 1 combines UDP compatibility, peer socket I/O statistics, server control, settings persistence, background services and the approved application icon. The release composes each feature's exact owned implementation through one application root.

Feature documents define each module's behavior and tests. This guide defines their interaction and the release's product-validation boundary. Source, parent, workflow and package references identify the same declared composition.

## Functional behavior

### Four-tab application

The tabs are Statistics, Server, Background and Settings. One SettingsStore owns durable configuration. One ServerController owns native server execution. One BackgroundKeepAlive holds the root's independent audio and location intent and registers with the process-level LoopAudioService. One PeriodicUDPEchoModel owns the independent Echo intent and runtime state. Changing the selected tab does not recreate those service owners.

An explicit audio choice reaches the audio service before the settings store accepts its memory value and queues its asynchronous save. Repeated On or Off choices are preserved even when their Boolean value is unchanged; a rapid Off-On pair reaches the service in that order. Server Stop similarly requests live shutdown before saving intent, including during initial loading or a load failure. Location Off also reaches the controller immediately; Location On retains the existing loaded-settings and permission flow. Start uses the loaded configuration when ready; a Start received earlier is retained and applied after loading merges the explicit edit with the saved fields. A storage failure remains visible while live intent takes effect, although durable intent can remain different until writing succeeds. If the store cannot allocate another intent revision, On and Start expose its terminal error before starting service work; Off and Stop still reach their service first and retain false in memory without reusing an identifier.

Automatic restoration waits for the store's ready state. Its nonpersistent change identity retains the accepted revision and user, load or import origin; the root compares the complete identity rather than a revision number alone. Four fixed service-intent stamps reuse that identity for audio, location, server running and UDP Echo. They preserve an accepted Off or Stop across unrelated setting edits while rejecting an older continuation after a newer choice for the same service, including an identical choice. Whole-snapshot load and import update all four stamps. A stored user change returns through the non-explicit synchronization path, so its echo, a tab change or a server edit does not manufacture another explicit audio recovery request. Loading and validated import use that same synchronization path. If a service publication synchronously accepts a newer input, the root also stops applying the rest of an obsolete settings snapshot.

A successful import can change running intent, Background choices and selected tab together; the server controller validates and serializes any replacement, while audio and location keep their own independent gates. The eleven server-configuration controls and Start remain disabled during the owned invocation, even though an import can request a replacement through the root. Stop has its own enabled condition: it remains available while either the controller owns an invocation or the current settings snapshot requests running, including while shutdown is in progress. Disabling configuration editing does not disable Stop.

A failed import rollback preserves the latest live intent and makes durability uncertainty visible. A ready Settings owner can explicitly save the latest Off again; an owner whose initial load failed blocks automatic rereading of the uncertain target until a validated explicit import succeeds. This prevents the rejected imported On from returning through restoration. The quarantine belongs to the current store instance in memory; this change adds no persistent recovery journal or quarantine guarantee across process death or power loss. The root retains its existing direct-service and readiness ordering.

Statistics counts successful socket work at both client and destination boundaries, by worker and normalized peer IP. In means bytes accepted by the OS for this program's writes to that IP; Out means bytes consumed by reads from that IP. Total sums those endpoint observations, so relaying 1,000 bytes from A to B contributes 1,000 A.Out and 1,000 B.In, before protocol bytes. Unresolved peer addresses use Unattributed. Stop retains the current server run's totals. Each actual new native server execution resets Total, per-IP volumes and rate baselines, including after application relaunch. Failed initialization and a pre-start Stop retain the previous session. Session checks discard a sample that straddles a restart and prevent old IP rows or rate baselines from carrying into the next run. Total/IP volumes and rates refresh together immediately on entry, then target the next device-clock `.0`/`.5` second boundary for each sampling start, only while Statistics is visible and the scene active. Each completed sample selects the next future boundary, skipping missed boundaries; exact execution times are not guaranteed. Rates use actual elapsed uptime, never wall-clock differences or a fixed 0.5-second divisor. Hiding or inactivation cancels sampling and skips row sorting and table formatting; a native read already in progress is not interrupted. Native accounting continues, and returning establishes a fresh zero-rate baseline. Peer addresses are decoded only for new visible sampler entries; existing labels reuse the same entry lookup. Statistics owns neither server lifetime nor durable configuration. Background audio/location can remain enabled while the server is stopped.

### Native and resource behavior

The release applies fourteen patches once: the UDP owner's eight-patch foundation, four Statistics patches, ServerControl's remaining patch and Background's read-only listener patch. It retains complete datagrams, strict peer/header/frame handling, the 1,500-byte base with 500-byte demand buckets, 300-second demand retention and 60-second cleanup checks. Darwin/Linux use exact-size allocation; the portable geometric probe can retain extra capacity until cleanup. Allocation or overflow failures in either sizing or reservation terminate the relay while preserving its queued datagram. Length-prefixed NAME destinations must be nonempty and preserve their complete identity before peer learning or frame completion; shared C-string construction rejects excessive lengths before changing output or allocating a client. CONNECT replies report the actual outgoing local endpoint after destination attribution is established. Serial startup DNS uses libc while running tasks retain their asynchronous resolver. DNS callbacks finish all proxy access before publishing a reply, and the existing initializer mutex prevents use of a reactor whose thread creation later fails. Interrupted request/reply operations retry while retaining their borrowed call state. Worker construction completes native session classes before worker threads start, and terminal setup state survives resumed I/O and address lookup. Resolved IPv6 destination scope survives shared address conversion, and unscoped destinations clear a stale output scope. Scoped NAME text uses the existing complete resolver path on Darwin as well as Linux. Initial authentication and connection responses require every encoded byte; an incomplete response terminates setup while its already accepted bytes remain accounted. Counter lifetime and IP attribution are independent of temporary buffer lifetime.

Socket and task-event registration must succeed before dependent I/O; failed UDP registration allocates no relay storage. Failed accept or session/task allocation attempts yield through the existing task timer, while successful admissions keep their normal path. A failure or exit in any worker stops the whole pool before joining it. Internal sibling shutdown and meter-entry failures do not carry a pending Stop into the next invocation, including when reported after the current send gate closes. A terminal event receiver clears its send state before later proxy Stop. Authentication uses worker-owned current state and an atomic pending reference, installs the initial value before accepting, and releases superseded or retained objects exactly once. Shared last-unref ordering precedes destruction. Library SIGUSR1 reloads use the first worker's existing event task and coalesced channel; the handler performs only lock-free state changes and a nonblocking notification. Shutdown unpublishes the worker and drains in-flight handlers before freeing it, joins every worker and finalizes the task systems, then restores the complete prior SIGUSR1 and SIGPIPE dispositions. Stack guard pages remain enabled while the optional per-thread diagnostic handler is disabled, preserving the host SIGBUS/SIGSEGV dispositions. The same inherited checks exercise these paths in the combined engine without changing meter ownership or server intent.

The fixed UDP port default and multiple-unknown-peer limitation remain. Socket accounting includes SOCKS negotiation, authentication, replies, UDP encapsulation, framing, consumed rejected input and successful prefixes before failure. It excludes peeks, unread or unaccepted bytes, internal copies, OS-generated headers, ACKs and kernel retransmissions. It does not measure remote delivery, interface traffic or billed data. Background retains its 0.5-second health/retry policy and original looping silent WAV; the icon remains a static catalog.

## Implementation and ownership

`AppRoot` owns the four StateObjects and binds the four tabs to the selected-tab setting. Both Settings and Echo StateObject factories share one lazy settings holder, so their first use constructs a single SettingsStore and a rebuilt root value with unused factories starts no storage I/O. The root injects the sole settings owner and actual-listener resolver into Background; the Echo client uses standard SOCKS5 network calls. Statistics and icon resources do not introduce reverse dependencies into those services.

These nine additions change the actual application Swift source count from twelve to twenty-one; the existing target inputs, build settings and original silent WAV remain intact. The checked immutable audio handle forwards into one private queue owner. Its control lane owns bounded scheduling and policy state, while its separate serial I/O lane exclusively owns the non-Sendable AV adapter; system callbacks submit immutable operation and generation receipts. One outstanding audio operation retains its real lifetime through Off, expiration or a delayed callback, including cleanup after the final external handle is released. A finite execution claim protects a transition and does not turn a blocked system call into a canceled operation. Settings has its own serial storage lane with one running and one latest pending save; audio never waits for that storage lane.

The inherited Background service measures a completed failure's retry deadline from actual reply availability and retains an earlier armed deadline within the same work context. An inspection that observes a stopped player reports that failure before reading its session or progress fields; category and mode mismatches similarly skip unnecessary later getters. Known failure remains distinct from fields that were never observed. A first inspection failure after accepted health starts a new recovery immediately. That recovery checks configuration when it actually starts, reusing a valid stopped player and rebuilding a misconfigured player. Healthy playback retains the ordinary progress observation path. Another owner's Off or unregistration preserves a surviving owner's retry deadline, blocked-asset state and pending explicit On. Completed aggregate Off clears the previous invalid-asset latch only after the actual stop returns. A changed restored/imported On then receives a fresh resource check; identical storage echoes and another owner leaving while aggregate intent stays On do not reopen the blocked attempt. Reusing a stopped player starts a fresh callback generation, so a delegate receipt from its earlier playback cannot invalidate that new lifetime. Its finite application claim is admitted by the current On intent and stop sequence for the whole recovery episode; a media resource epoch change cannot consume that episode's only protection request. Actual AV calls retain their separate resource epoch guard. An accepted healthy playback and configuration result ends the finite claim and closes that episode together. A real failure after that recovery can request one claim for a new episode even before the next health inspection. Denied, expired or missing protection does not renew a continuously failed episode. This playback confirmation does not certify physical output. The existing I/O operation resumes only after the actual UIKit begin call returns or the latest Off prevents its issue. The thread-safe begin runs on the requesting I/O lane; short checked metadata locks coordinate its result with MainActor end and expiration. Ordinary expiration ends an available platform ID before returning. Unknown-ID expiration is reported immediately, with the returned ID later released before receipt and audio continuation. Reentrant end retains ownership until the actual platform end returns, and one queued-end reservation prevents duplicate cleanup jobs or overlapping platform claims. Logical identity rejects stale callbacks even if UIKit reuses a raw identifier. Normal provider return remains distinct from receiving a grant. Start admission incorporates the latest resource epoch before choosing reuse or reconstruction, then consumes only the matching pending invalidation. Delayed control-queue delivery of an already incorporated invalidation cannot replay a completed recovery; a later invalidation still revokes its replacement. iOS 27 application-requested deactivation remains a health-check hint; system, missing and malformed contexts retain resource invalidation. The integration adds no audio worker, request renewal, timer or claim owner.

Periodic UDP Echo is a real independent SOCKS5 client: TCP negotiation and optional authentication precede CMD 0x03 UDP ASSOCIATE, then the client sends a SOCKS5-framed UDP request to the returned relay endpoint for each configured numeric destination. Successful writes record local socket acceptance; destination delivery can remain unconfirmed when Off closes the association. Server replacement, reconnects and input edits while On retain the count; Off retains its final value and the next On resets it. Count-only publication uses the existing timer at most twice per second. The row explicitly exposes the accessibility name `Sent` and the numeric count as its value. Defaults are Off, `1.1.1.1` and 1000 milliseconds. Commas or newlines separate up to 65,536 normalized unique IP addresses; IPv4-mapped IPv6 normalizes to IPv4, and scoped text or IPv6 targets requiring an interface scope are rejected. On waits for the actual admitted server invocation and listener, using that invocation's authentication snapshot. Replies are consumed when available; absence of replies neither delays sending nor triggers transport recovery. One utility queue and timer schedule bounded batches through at most two lazy client associations, with no catch-up burst or per-request reply tracking. Echo Off and server Stop close client admission immediately; stopping the server preserves saved Echo intent. Load/import restoration cannot revive a superseded intent. A single SettingsStore owns persistence, including strict additive `background.periodicUDPEcho` values and raw drafts without a JSON byte cap.

The root adapts the client's actual-peer I/O observation to one Statistics writer. It neither counts the embedded destination as a socket peer nor performs packet-time snapshot work. The writer survives service Off and server replacement, but each record belongs to the current native statistics session; initialization failure visibly waits before any client socket is created. The small listener patch only exposes read-only actual endpoint metadata. The common native lifecycle patch is deduplicated by filename and byte identity; the ServerControl projection omits only the exact stronger UDP-authentication overlap.

## Design rationale and resource cost

Composition through one root makes ownership visible and prevents service lifetime from following tab visibility. Keeping persistence, server intent, background recovery and measurement separate avoids duplicated sources of truth. Exact feature mappings allow the release to reuse implementation rather than maintain parallel copies with different behavior.

Integration adds no separate runtime management layer. Costs remain in datagram sizing, bounded NAME scans, adaptive buffers, process-lived IP/worker entries, counter publication, visible snapshot/sort work, server/AudioSession operations and audio/location scheduling. Session initialization uses the existing cached class lookup during serial worker construction, and terminal checks reuse existing association state. Authentication adds no pointer storage and strengthens the existing atomic reference decrement. DNS uses the existing initialization mutex when creating a task DNS proxy and adds no per-packet lock. Signal reload adds one optional internal callback pointer per worker and fixed process-level atomic/disposition storage, reusing the existing task and descriptor pair. Signal accounting is outside packet processing. Reader retries are not bounded, although writers do not wait for readers. Buffer release need not immediately reduce RSS. No universal CPU/RAM minimum or physical battery improvement is asserted.

Root synchronization retains one last-applied change identity. It adds no timer, per-event history or second audio owner. The audio service retains the original 0.5-second health/retry policy and one bounded scheduler. When the scheduler arms a timer while playback is unhealthy, it requests Dispatch strict scheduling with the existing 1-millisecond leeway. The next scheduling update after accepted healthy playback restores an ordinary timer. The active source is replaced only when its mode changes, preserving an earlier deadline within the same work context and rejecting old source callbacks. Repeated failures reuse the same source. This best-effort scheduling request can increase recovery power consumption and does not guarantee a wake-up deadline; queue QoS remains unchanged. Bounded progress corroboration uses limited additional samples and does not equate a moving clock with verified physical output. File-position reporting precision is independent of I/O buffer duration. Unknown precision cannot turn a stationary report into a suspected stall, and speculative recovery remains disabled without the required environment-specific false-positive acceptance. The current API-step entry/return and asynchronous callback receipt/consumption have separate bounded diagnostics; neither method return nor a moving clock is presented as proof of physical rendering. Normal playback reuses its player and original WAV data instead of allocating a periodic replacement.

Source and artifact checks are build-time work. They verify that the product links the declared feature engine and carries correct resources, not that every operating-system or network condition is supported.

## Operation and limitations

Use a full-history clean checkout. The release commands are `bash Build/build.sh`, then on an Apple host `bash Build/check_swift_sdk.sh`, `python3 Build/verify_release.py`, `python3 Build/simulator_review.py`, `python3 Build/ui_review.py` and `python3 Build/record_evidence.py`. The workflow selects the applicable platform stages; an Apple-only skip on Linux is not an executed check.

Archive and Simulator builds explicitly set version 3.0.0 and build 1, and package checks read those values from the actual Info.plist. For a manual device-product build, the Apple path defaults `BUILD_IPA` to `1`; it can be set explicitly as in the release workflow. Setting `BUILD_IPA=0` skips archive generation. The following product/Simulator checks require that generated product and their source/native prerequisites; they do not build a missing archive implicitly. The delivered product is unsigned input for a signing or import process, not a device installation. Documentation edits neither alter that product nor replace its separately recorded source and hash.

Documentation verification uses `python3 Build/check_documentation.py` and the document-specific regression fixture. Add `--live-parents` to require the declared document parents to match the current remote branch tips; the default check verifies the pinned snapshot reproducibly. It preserves the frozen application, test oracles, build/workflow configuration, defaults and resources. A document-only commit is not a new runtime test or product build.

The configured minimum is iOS 17.2 and the primary physical deployment target is iOS 27. SideStore standalone signing/install/run and LiveContainer guest/shared-host execution require separate records. An unsigned IPA, changed Simulator identifier or SDK compile does not prove either physical route. Permission/file-protection states, external provider transfers, calls/Siri/Bluetooth, VPN/hotspot, suspension, long locked-device operation and device resource measurements remain separate deployment tests.

The fixed-port unknown-peer restriction, independently collected worker parts, finite counter/display precision and process-lifetime registry storage are explicit contracts; the displayed accounting values reset at each server session. Persistent On is intent, not guaranteed execution or permission. Finite passing tests do not prove the absence of every possible input, allocator, scheduler or host failure.
