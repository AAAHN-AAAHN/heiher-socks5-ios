**"기존 코드와 확정된 동작을 먼저 이해하고 보존한다. 필요한 부분만 최소한으로 수정하며, 단순하고 간결하면서 자원 효율적인 구현으로 핵심 목적을 정확히 달성한다. 표준·권장 문법과 기존 스타일을 지키고, 기능의 책임을 명확하게 분리하면서 자연스럽게 통합한다. 모든 변경과 관련 문맥을 철저히 검증하고, 구현 내용뿐 아니라 이유·목적·범위·비용·검증 결과·한계까지 상세히 문서화한다.**

**모든 코드 작업은 iOS 27 실기기에서 SideStore로 설치하거나 LiveContainer 안에서 실행하는 사용자의 실제 환경을 기본 전제로 한다. 설계·API 선택·구현·패치·검수·빌드·IPA 제공·설치 안내의 전 과정에서 이 환경을 먼저 고려한다. SideStore 독립 설치와 LiveContainer 게스트 실행을 구분하고, 일반적인 Xcode 직접 설치·App Store 배포·시뮬레이터 환경을 사용자의 실제 환경과 동일하게 간주하지 않는다. 환경 차이에 대응할 때도 기존 동작 보존·최소 수정·단순성·자원 효율 원칙을 유지하며, 확인되지 않은 원인을 근거로 호스트 변경이나 불필요한 우회·진단 기능을 추가하지 않는다.**

**README는 기능 설명뿐 아니라 지원 대상 버전·설치 환경·정확한 구현 범위·설계 이유·사용 조건·검증 근거·알려진 제한을 기록하는 기준 문서로 유지한다. 설정된 최소 OS, 지원 대상으로 삼는 환경, 실제 빌드한 환경, 실제 실행하여 확인한 환경을 구분한다. 코드나 검증 결과가 바뀌면 관련 문서도 함께 갱신하되, 확인하지 않은 동작을 지원·검증 완료로 표현하지 않는다.**

**완료 여부는 실제 근거로 판단한다. 코드 검사, 모의 테스트, SDK 컴파일, IPA 생성, 전체 CI 통과, SideStore 설치 후 실기기 실행, LiveContainer 내부 실행, 실기기 백그라운드 동작을 서로 대신하는 증거로 사용하지 않는다. 성공·실패·미실행·미확정 상태를 구분하고, 제공한 소스와 IPA가 어떤 커밋·빌드·검사 결과에 대응하는지 추적 가능하게 남긴다."**
