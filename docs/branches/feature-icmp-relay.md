# Native ICMP Echo relay

## Purpose and scope

This feature adds a reusable native ICMP Echo engine to the HEV core and exposes a local C ingress through the HEV SOCKS5 server. It accepts an already received standard Echo message, its source and destination addresses, and a caller-owned return context. A local client uses the same engine through a small Echo8 convenience function.

The native sources remain the locked upstream server and core, with the UDP compatibility owner's prerequisite patches followed by the two ICMP patches. The independent tunnel checkout remains at its upstream implementation. SOCKS5 CONNECT and UDP ASSOCIATE retain their existing protocol. This feature introduces no SOCKS command or custom client wire format.

A local API is an explicit integration boundary. Ordinary remote `ping` traffic must first reach an ingress adapter through an appropriate routed or captured IP path; connecting a conventional SOCKS client does not deliver ICMP to this API. This owner implements the native Echo service and the local client API. A remote network ingress, TUN packet adapter, IP-header reconstruction, Ethernet bridging and advertisement forwarding are outside this owner's scope.

## Functional behavior

### Request and reply contract

The public API is declared in `src/hev-socks5-icmp.h` and included by `src/hev-main.h` after native patches are applied. `hev_socks5_server_icmp_generation()` returns zero until worker 0 has registered its listening socket and ICMP wake descriptor and completed native bind configuration. A client is created for one nonzero ready generation and cannot migrate to a later server run.

`hev_socks5_server_icmp_submit()` takes an ICMP Echo message, including the eight-byte Echo header and any payload, without an IP header. IPv4 type 8/code 0 and IPv6 type 128/code 0 are accepted. Input IPv4 checksums are validated; an IPv6 input with an original source also validates its pseudo-header checksum. Numeric unicast destinations, IPv4-mapped IPv6 normalization and scoped IPv6 link-local destinations are supported. Zone values are retained for link-local destinations and normalized to zero for other unicast IPv6 addresses so the received peer has the same endpoint identity. Unspecified or multicast addresses and malformed Echo messages fail explicitly. The maximum message lengths are 65,515 bytes for IPv4 and 65,535 bytes for IPv6; the network, OS and path MTU may impose a smaller usable size.

`hev_socks5_server_icmp_ping()` constructs an Echo8 message using the same core generator and submits it through that ingress. The configured bind address and interface apply to the native socket, or the OS selects a local source. The optional original source argument identifies the logical return destination and does not request outgoing IP-source spoofing. The local convenience path supplies no original remote source.

Identifier and sequence values are replaced on the network leg so simultaneous clients can use identical original values without sharing reply ownership. An accepted reply must match the current socket identifier, active sequence, actual peer, message length and payload. The result restores the original identifier, sequence and return address, with the corresponding IPv4 or IPv6 checksum. Payload bytes remain unchanged. An expired, foreign, malformed, truncated or unmatched packet produces no successful reply callback.

Return zero means the input was copied into the bounded native queue. A negative errno means immediate rejection and no callback. Accepted requests emit `HEV_SOCKS5_ICMP_SENT` only when the OS accepted the entire Echo message. They subsequently emit `HEV_SOCKS5_ICMP_REPLY` for a matching received Echo Reply or `HEV_SOCKS5_ICMP_ERROR` for a terminal failure. A send failure emits ERROR without SENT. A positive partial send is counted as an actual transfer but terminates with `EIO`. Timeouts are explicit from 1 through 60,000 milliseconds and start at successful transmission. A related received ICMP error terminates only its matched request with ERROR. Local socket failure, received ICMP error, no-response timeout, requester cancellation and server shutdown have separate `error_origin` values. A request without a matching reply or a sufficiently identified error ultimately times out.

### Received ICMP errors

The three existing event values remain SENT, REPLY and ERROR. Result metadata appended after the existing fields records `error_origin`, `icmp_type`, `icmp_code` and `icmp_info`. Only `HEV_SOCKS5_ICMP_ERROR_RECEIVED` carries the ICMP type/code and any OS-provided MTU or parameter pointer; `icmp_info` is host order and zero when unavailable. The errno remains available for all failures. `echo` is NULL for an error: neither the error message nor its quoted request is presented as a successful Echo Reply. Existing consumers that handle ERROR without reading the appended metadata retain their behavior.

Related IPv4 Destination Unreachable, Time Exceeded and Parameter Problem, and IPv6 Destination Unreachable, Packet Too Big, Time Exceeded and Parameter Problem are recognized. Matching uses the original network destination, address family, current socket identifier, active wire sequence and the available quoted Echo payload. The actual error sender can be an intermediate router. On a received error, `source` is that sender when the OS provides it; it is never replaced by the request target. `destination` remains the logical return recipient, or the local receiving address when available. The caller retains the request target under its own request identifier. Missing, malformed, foreign, truncated or noninitial-fragment quotes cannot terminate another request. Duplicate and late errors do not create another terminal callback. Deadline, cancellation and server-stop rules still apply.

Linux enables `IP_RECVERR` / `IPV6_RECVERR` and reads `MSG_ERRQUEUE` separately from ordinary Echo replies. It distinguishes kernel LOCAL records from actual ICMP/ICMP6 origins. The original destination in `msg_name` identifies the request target; `SO_EE_OFFENDER` identifies the error sender. Optional RFC 4884 quote-boundary metadata excludes extension objects from payload matching. A socket errno alone does not identify a different pending request: after a negative send, the worker drains the error queue outside the admission lock, then yields before reconsidering the unsent request. A newly consumed asynchronous network error, or a LOCAL error assigned to another active request, permits retrying that unsent request. With no such evidence, the original local send errno terminates it after that yield. This immediate retry scheduling is separate from identifier-rollover waiting, so an unrelated long deadline cannot delay the new send.

Darwin delivers error messages on the ordinary datagram receive path. The parser follows the platform's delivered format: XNU has already checked the IPv4 ICMP checksum and changed the quoted IPv4 total length to host order. IPv4 header options and explicit RFC 4884 quote lengths are bounded before accessing the Echo header. The IPv6 parser bounds Hop-by-Hop, Routing, Destination Options, Fragment and Authentication headers to eight extensions and the bytes actually returned by the OS; noninitial fragments, unsupported next headers and incomplete chains remain unassociated. Scoped link-local targets use the receive interface from `IPV6_PKTINFO`. The engine does not invent a missing quote, decrypt an opaque payload or reconstruct an IP packet for the caller.

### Cancellation, lifecycle and I/O observation

Callbacks run serially on native worker 0, and result storage is borrowed only for the callback duration. Callbacks must return promptly and must not destroy a client or stop/join the server. Each callback includes the caller's request identifier; the callback context belongs to its client. A caller can keep additional request state keyed by that identifier.

Cancel invalidates requests accepted before the call, including queued submissions. Once cancellation returns, those submissions cannot begin a later send. Client free also waits for an active callback and prevents subsequent use of its context. The caller must serialize free against its own other handle accesses. Server stop disables new admission immediately, wakes worker 0 and drains queued and active state before the native server call returns. Restart publishes a new generation, so stale clients fail with `ENOTCONN`.

`hev_socks5_server_icmp_set_io_observer()` installs an optional callback while the native service is stopped. It runs synchronously on the same native worker immediately after positive socket I/O, before reply validation or cancellation filtering. The observer receives the actual peer, byte count and direction. Reads count bytes actually copied into the application buffer, clamped to capacity if an OS reports a larger truncated length. A network error with no known offender uses `peer == NULL` and `peer_len == 0`, allowing unattributed traffic to remain unattributed. Linux error-queue observation counts only the positive returned quoted-Echo bytes; ancillary metadata, unavailable outer IP/ICMP headers and locally generated error records add no network read bytes. Darwin error-message reads count the actual returned ICMP message. The original request destination is never substituted for a missing error sender. Writes count the positive byte count accepted by the OS, including a hypothetical partial write. Zero-transfer failures, internal C calls, queue movement and wake-pipe signaling add no network bytes. The observer must return promptly and must not reenter the ICMP API. The server wrapper preserves the syscall's `errno` across observation.

The callback is optional and creates no dependency on the Statistics feature. The Statistics owner can attach its ordinary socket-I/O adapter. No own-IP request or reply bytes are invented for the in-process client; local-IP traffic is counted only when it actually crosses the application's socket boundary.

## Design rationale and resource cost

One worker owns all ICMP socket operations and reply state. A lazily opened datagram ICMP socket serves each address family, so thousands of targets do not require thousands of sockets, TCP sessions or independent native tasks. There is one ICMP coroutine with a 64 KiB stack and one nonblocking wake pipe. At most two ICMP descriptors are open. A coalesced pipe wake lets producers submit from another thread without polling an idle service.

Native admission is limited to 1,024 live client handles, 4,096 pending requests and 16 MiB of retained Echo messages, including queued and active submissions. Reaching either pending limit returns `EAGAIN` without allocation or partial admission. Each message is copied once. Per-request metadata and allocator overhead are additional bounded costs. On the measured Linux x86_64 ABI, the request metadata grows from 320 to 336 bytes and the borrowed public result from 296 to 312 bytes. At the 4,096-request limit that is 64 KiB of additional retained request metadata; these are host ABI measurements, not universal platform sizes. The send-retry snapshot and error-generation counters are compiled only on Linux. Apple retains the common error metadata without that Linux state. The direct sequence lookup table uses 65,536 pointers, allocated on the first send, and one 65,535-byte receive buffer is reused. An active socket requests a 128 KiB send buffer and 256 KiB receive buffer; the actual OS allocation policy remains platform dependent.

Each worker cycle admits at most 256 queued submissions and consumes at most 64 received messages per family before yielding, with error-queue records and ordinary packets sharing that limit. A direct sequence table avoids scanning every pending request for each reply. Deadline and cancellation scans remain bounded by the pending-request limit. Identifier space rotates only after outstanding requests have drained, avoiding reuse of an active mapping. An already admitted request awaiting that rotation remains at the queue head and resumes after reply or timeout drainage; it is not reported as a failed send. The native task waits for I/O or the earliest pending deadline during that interval and resumes immediately if polling drained the last outstanding request. This internal deferred outcome is distinct from every syscall errno, including actual send failures such as `EAGAIN` or `EBUSY`. Identifier fields are finite; they cannot provide a cryptographic identity or an unbounded replay guarantee.

The engine, server lifecycle adapter and optional statistics observer have separate responsibilities. The API and helper functions stay small because a dedicated worker and a fixed pair of socket paths replace per-target session objects or multiple parallel implementations.

## Verification contract

Run `python3 Tests/ICMP/audit.py` from a clean committed owner checkout with clang-format 18, a native C compiler and functional IPv4/IPv6 loopback. The audit verifies the committed source archive and full source pins, exact patch application and reversal, upstream C formatting, documentation and composition contracts, native ICMP behavior, and inherited TCP/UDP traffic. On the Apple runner it also compiles all changed native sources against the actual iOS 27 SDK. No IPA is packaged by this independent audit.

The actual native tests cover all 65,536 generated IPv4 sequence checksums, the IPv6 Echo8 format, real IPv4 and IPv6 loopback, large Echo messages, multiple clients with identical original identifiers, restored payload and checksums, an already received IPv6 request with a separate logical return source, immediate invalid-input rejection, cancellation before transmission, callback quiescence, count and byte admission bounds, stop/restart and stale-generation rejection.

A separate Linux linker-wrapper mode injects socket-creation and send errors, a positive partial write, a missing reply, a foreign identifier and receive truncation. It checks terminal events, actual-byte observation, shared socket count and descriptor release. The production engine is also driven through all 65,535 usable wire sequences, with a pending request held across rollover, to verify deferred admission and resumption. Additional controls check server queue-head retention, a response read after its deadline being counted but expiring, and non-link-local IPv6 zone normalization. These deterministic socket-pair tests are identified as simulated I/O and do not substitute for the real ICMP gate. `python3 Tests/ICMP/run.py PATH_TO_PREPARED_NATIVE_SOURCE --faults-only` is a diagnostic Linux command, not an acceptance result for native ICMP availability.

`Tests/ICMP/errors.c` compiles the actual prepared engine with six explicitly replaced socket operations and runs on both Linux and Darwin. Its deterministic inputs cover both families, every supported error category, minimum eight-byte Echo quotes, wrong identifier/sequence/target/payload, truncation, RFC 4884 boundaries and padding, IPv6 extension and scope boundaries, unknown offenders, local versus network origins, duplicate terminal suppression, deadline/cancel/stop precedence and the shared 64-message drain limit. The native Linux server fixture also injects an old request's error exactly as a new send fails while a third request has a 60-second deadline. It verifies that the new request is promptly sent and receives its own reply, while the third request stays independent. The pre-change engine fails the received-error terminal assertion without relying on a new-structure compile failure. These fixtures establish deterministic behavior; real kernel delivery is a separate gate.

`Tests/ICMP/live_errors.py` is the separate real-delivery gate for both operating systems. The engine runs as the ordinary non-root runner user with production datagram socket setup, receive calls and parsing. Its test-only send wrapper first makes a real Echo send and consumes the kernel's automatic loopback Echo Reply through a separate fixture read. A separate noninteractive `sudo` injector then sends a real loopback Time Exceeded packet quoting that transmitted Echo. The engine subsequently consumes that error through its unchanged receive path: Linux `MSG_ERRQUEUE` or Darwin ordinary `recvmsg`. This deliberately controlled reply consumption is a test precondition, not application behavior. Only the injector has raw-socket privilege; the engine receives no privilege escalation. The fixture uses IPv4/IPv6 loopback exclusively, changes no system network settings, and records both process identities and the actual kernel-delivery result. Missing privilege separation or raw-injector capability fails the real gate explicitly. The local `--faults-only` diagnostic excludes this live gate and cannot establish real socket availability.

The CI Linux runner explicitly permits its test group to open datagram ICMP sockets before running the strict real gate. A permission failure, missing IPv6 loopback, native timeout or any assertion failure fails that gate. The workflow records the actual runner policy and Apple toolchain in its output. `SUCCESS.txt` is written only after all applicable audit checks and source restoration pass. Functional source identity and parent document provenance are frozen in the branch's documentation contract.

## Operation and limitations

The operating system must allow `SOCK_DGRAM` ICMP/ICMPv6. Linux permission depends on the runner or host's ping-group policy. Apple socket behavior is exercised on the native Apple CI host and the actual iOS SDK is a compilation gate; neither proves installation permissions or suspension behavior on a physical iOS device, SideStore or LiveContainer. Those environments require device validation before making device-runtime claims.

An idle native server opens no ICMP sockets until a request needs its address family. Permission, bind, interface, resource and send failures are returned through the native API. There is no raw-socket privilege escalation or silent simulated reply in production. Existing server bind-address, interface and mark settings govern outbound sockets. The relay emits a new OS-managed IP packet and preserves the Echo payload and logical reply identity; original IP headers, TTL, fragmentation layout and network path are not replayed by this API.

A higher-level local client should wait for a nonzero generation, allocate a client, submit bounded batches and handle capacity errors without a busy retry loop. On an Off action it should close its own submission admission, cancel, and free the handle when concurrent callers no longer retain it. No GUI-running flag replaces native readiness. This owner supplies no timer, audio background service, application settings, UI, traffic store or automatic remote routing configuration.
