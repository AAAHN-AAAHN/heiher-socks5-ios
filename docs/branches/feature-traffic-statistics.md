# Peer socket I/O statistics

## Purpose and scope

Statistics shows cumulative volume and observed transfer rate for Total and each peer IP used by the SOCKS server. It counts completed socket work at both client and destination boundaries, including work completed before a later error or cancellation. Native accounting continues independently of UI visibility.

The feature inherits UDP compatibility and adds the socket meter, its public snapshot API and the Statistics view. Server controls, persistence, background behavior and installation policy remain separate features.

## Functional behavior

### Measurement boundary

Directions use the peer IP's viewpoint:

- **In:** bytes successfully accepted by the OS for this server's writes **to that IP**.
- **Out:** bytes consumed by this server's reads **from that IP**.

Client and destination peers use the same rules and IP registry. A read from A adds A.Out; a write to B adds B.In. Total sums these endpoint observations. Relaying 1,000 bytes from A to B can therefore contribute 1,000 to each direction of Total, before protocol bytes. It is not a count of unique forwarded content or a remote-delivery acknowledgment.

SOCKS negotiation, authentication, requests, replies, UDP encapsulation and stream framing are included at the sockets where they are transferred. Consumed rejected input and successful prefixes before failure remain counted. Requested-but-unaccepted writes, unread bytes, peeks, size probes and internal pipe movement do not contribute additional bytes. A truncated UDP receive counts bytes copied into the supplied buffers; a larger MSG_TRUNC result does not add the discarded suffix. An empty datagram contributes zero bytes. Repeated application data counts again when another successful socket operation transfers it.

IP/TCP/UDP headers generated by the OS, ACKs, kernel retransmissions, system-resolver internals and traffic bypassing this server are outside this boundary. These values are not interface, radio, billed-data or IPFIX packet-octet totals.

The actual socket peer determines attribution. TCP caches the connected peer, retaining the successful connect address if peer lookup becomes unavailable. IPv4-mapped addresses normalize to IPv4; native IPv6 scope identifiers remain distinct. Unspecified addresses (`0.0.0.0`, `::` and mapped equivalents) cannot identify a peer and use Unattributed, as do unresolved peers and allocation failures. Both roles and all ports for one normalized IP share an entry. An IP identifies an observed endpoint, not a person or device. Connection closure and Stop retain the current server run's totals. The next actual native server execution starts a fresh statistics session: Total, per-IP volumes and rate baselines reset together, including after an application relaunch. Initialization failure and Stop before execution begins do not erase the previous session.

### Rate and display

`TrafficStatistics` computes rates from cumulative-counter differences divided by actual elapsed monotonic time. The first sample, non-increasing time or decreasing counters establishes a zero-rate baseline. Raw counters and rates remain separate from display rounding.

The existing tables show **In**, **Out** and **In + Out**, with **Spd.** and **Vol.** rows. The sum is formed before rounding. Volume uses SI KB/MB/GB/TB/PB; speed converts bytes per second to SI Kbps/Mbps/Gbps/Tbps/Pbps. Both use exactly two decimal places and a fixed formatting locale.

A single visibility/scene-keyed task updates Total/IP volumes and rates together immediately, then targets each next device-clock `.0`/`.5` second boundary for the start of sampling, only while the tab is visible and the scene active. After each sample it calculates the remaining delay to the next future boundary; missed boundaries are skipped, and exact execution times are not guaranteed. A clock change during a pending sleep is reflected when the next delay is calculated. Rates still use actual elapsed uptime, never wall-clock differences or a fixed 0.5-second divisor.

The same visibility/scene condition gates row sorting and table formatting. Hiding or inactivation cancels sampling cooperatively; a native read already in progress is not interrupted. Native accounting continues without periodic display aggregation. Returning establishes a fresh zero-rate baseline and shows the current server session's native volume. A restart while hidden is therefore reflected on re-entry. `EndpointTrafficStatistics` caches entries by stable ID and sorts those IDs; IDs may have gaps and do not index the native row array. Nonzero Unattributed appears first.

Linux UDP GSO groups pass through the same socket observer as ordinary UDP sends. The OS-accepted length of each completed group is counted once for the actual relay peer; it is not multiplied by the group's datagram count. IP/UDP headers created by the kernel remain outside this socket boundary, and the counter/rate definitions are unchanged on Darwin.

## Implementation and ownership

Statistics owns the native accounting, snapshot aggregation and display as separate responsibilities. The integrated release inherits the same implementation; `AppRoot` only connects the feature to the application's tabs. Other feature branches do not own or duplicate the meter.

Four Statistics patches follow the eight inherited UDP patches in `Build/features.json`, producing one ordered twelve-patch native composition:

- `hev-socket-meter-task.patch` observes successful socket results, including partial WAITALL and multi-message progress before an error or yield. Existing helper entries use a null observer and retain their I/O behavior.
- `hev-socket-meter-core.patch` owns the common worker/IP counters and connects both peer roles to the observed socket helpers. TCP retains peer references, including the address supplied by accept; UDP uses the actual message peer and caches its connected relay peer separately from the TCP control peer.
- `hev-socket-meter-server.patch` owns worker lifecycle integration and the public endpoint snapshot API.
- `hev-socket-meter-writer.patch` exposes a caller-owned serialized socket-I/O writer using the same counter store.

The UDP prefix includes nonempty NAME identity and bounded construction, actual CONNECT BND replies, task-appropriate startup DNS, DNS reply and initializer lifetime, worker authentication publication/reference ownership, library signal reload lifetime, session class initialization before worker threads start and terminal handling across setup waits. The Statistics patches apply to that exact native preimage and retain their existing accounting changes. UDP owns those transport and setup invariants; Statistics owns observation and aggregation of the socket work that actually completes.

Each worker writes its own counters for each IP. Ordinary I/O updates do not take a global counter lock or modify a shared Total counter. CAS coordinates new identity metadata and worker ownership. A standard pthread key binds worker storage to its native thread; storage becomes reusable only after that thread's native tasks stop. The registry and stable identities live for the process, while accumulated values belong to one server session. A failed worker-meter entry uses the proxy's internal pool-stop path. Even if a sibling reports failure after finalization closes the send gate, it cannot queue a Stop for the next invocation.

Private 64-bit values are published through C11 32-bit atomic words with release/acquire ordering and sequence/epoch checks. Acquiring the initial epoch and both sequence reads orders the checks across sequence wrap. Readers retry until each current-session worker part is coherent; this implementation does not impose a fixed retry limit. A separate 32-bit session generation excludes old counters and old IP rows without externally clearing a live writer's private fields. Each writer captures the current session when recording actual I/O and lazily clears its own prior values on its first new-session record. A delayed publication from an older session cannot contaminate a newer session or move an identity backward. Writers do not wait for readers. Readers merge parts by IP, and Total merges the same endpoint data. Separate Total and row calls are not one simultaneous snapshot while traffic is changing. Allocation and pthread internals are not claimed to be lock-free.

`hev_socks5_server_endpoint_generation()` identifies the current statistics session. The native run boundary advances it after the pre-start Stop guard and before workers are released. Generation exhaustion rejects a later start rather than reusing a session identity. `hev_socks5_server_endpoint_stats()` fills two non-null outputs: `received` means peer In and `sent` means peer Out. `hev_socks5_server_endpoint_rows(nil, 0)` queries required capacity, including ID 0, using identity metadata without reading counters. A copy call packs up to the supplied capacity into caller-owned `HevSocks5EndpointStats` rows and returns the current required count. Stable IDs are independent of packed-array positions. No registry pointer escapes through the API.

The view performs one capacity query and one bounded row copy per sample, then publishes one local dictionary snapshot. It reads the session generation around that complete sample. A changed session clears Total, IP rows and rate baselines together; a restart during sampling discards the mixed sample and displays the cleared new session until the next regular sample. Native addresses are decoded only when an ID first enters the visible sampler cache; existing labels are reused without another lookup. Concurrent registration can defer some row updates across multiple samples; cached rows remain while later samples retry the bounded copy. This UI copy bound does not limit the native coherent-counter retry loop.

`SocketIOWriter` is an explicit serial-queue producer for application-owned standard SOCKS5 sockets. Its C handle uses the same counter store as native workers without relying on thread-local storage, because a dispatch queue may migrate between OS threads. Only actual positive read/write results are recorded, against the actual TCP server or UDP relay peer; SOCKS headers and authentication bytes therefore count. Allocating a producer does not require a running native server, and completed totals survive producer release within the same statistics session. A writer can outlive a server replacement; its next record uses the new session, so retaining the writer does not retain the preceding run's totals. The wrapper adds no timer, per-packet snapshot, payload decoding or second traffic table. If allocation fails, the integrated Echo service waits visibly before creating sockets and retries through its existing scheduler.

## Design rationale and resource cost

Worker-local counters remove shared per-I/O Total updates. Registration, allocation and snapshot merging still have costs. Process-lived storage grows with distinct IPs and the workers that used them. The visible-and-active gate avoids periodic snapshot, rate, sorting and formatting work while the tab is hidden or the scene inactive. Counters and publication tags have finite range, and large values lose precision when converted to Double for display.

## Operation and limitations

The inherited UDP fixed-port, multiple-unknown-peer restriction remains. Statistics does not change routing, prove remote delivery or identify a device behind a shared IP. The UDP prerequisite supplies session class initialization and terminal setup handling. The inherited `hev-server-lifecycle.patch` corrects the worker pre-wait early-Stop race.

Physical iOS 27 SideStore standalone and LiveContainer guest operation, device resource measurements and non-Linux native runtimes require separate execution evidence. A configured minimum iOS version or a successful source build does not establish those results.
