# Peer socket I/O statistics

## Purpose and scope

Statistics shows cumulative volume and observed transfer rate for Total and each peer IP used by the SOCKS server. It counts completed socket work at both client and destination boundaries, including work completed before a later error or cancellation. Native accounting continues independently of UI visibility.

The feature inherits UDP compatibility and adds the socket meter, its public snapshot API and the Statistics view. Server controls, persistence, background behavior and installation policy remain separate features.

## Functional behavior

### Measurement boundary

Directions use the peer IP's viewpoint:

- **In:** bytes successfully accepted by the OS for this server's writes **to that IP**.
- **Out:** bytes consumed by this server's reads **from that IP**.

Client and destination peers use the same rules and IP registry. A read from A adds A.Out; a write to B adds B.In. Total sums these endpoint observations. Relaying 1,000 bytes from A to B can therefore contribute 1,000 to each direction of Total, before protocol bytes. It is not a count of unique forwarded content or a remote-delivery acknowledgment.

SOCKS negotiation, authentication, requests, replies, UDP encapsulation and stream framing are included at the sockets where they are transferred. Consumed rejected input and successful prefixes before failure remain counted. Requested-but-unaccepted writes, unread bytes, peeks, size probes and internal pipe movement do not contribute additional bytes. A truncated UDP receive counts bytes copied into the supplied buffers; a larger MSG_TRUNC result does not add the discarded suffix. An empty datagram contributes zero bytes. Repeated application data counts again when another successful socket operation transfers it.

IP/TCP/UDP headers generated by the OS, ACKs, kernel retransmissions, system-resolver internals and traffic bypassing this server are outside this boundary. These values are not interface, radio, billed-data or IPFIX packet-octet totals.

The actual socket peer determines attribution. TCP caches the connected peer, retaining the successful connect address if peer lookup becomes unavailable. IPv4-mapped addresses normalize to IPv4; native IPv6 scope identifiers remain distinct. Unspecified addresses (`0.0.0.0`, `::` and mapped equivalents) cannot identify a peer and use Unattributed, as do unresolved peers and allocation failures. Both roles and all ports for one normalized IP share an entry. An IP identifies an observed endpoint, not a person or device. Stop/Start and connection closure retain process totals; a new application process starts fresh.

### Rate and display

`TrafficStatistics` computes rates from cumulative-counter differences divided by actual elapsed monotonic time. The first sample, non-increasing time or decreasing counters establishes a zero-rate baseline. Raw counters and rates remain separate from display rounding.

The existing tables show **In**, **Out** and **In + Out**, with **Spd.** and **Vol.** rows. The sum is formed before rounding. Volume uses SI KB/MB/GB/TB/PB; speed converts bytes per second to SI Kbps/Mbps/Gbps/Tbps/Pbps. Both use exactly two decimal places and a fixed formatting locale.

A single visibility/scene-keyed task updates Total/IP volumes and rates together immediately, then targets each next device-clock `.0`/`.5` second boundary for the start of sampling, only while the tab is visible and the scene active. After each sample it calculates the remaining delay to the next future boundary; missed boundaries are skipped, and exact execution times are not guaranteed. A clock change during a pending sleep is reflected when the next delay is calculated. Rates still use actual elapsed uptime, never wall-clock differences or a fixed 0.5-second divisor.

The same visibility/scene condition gates row sorting and table formatting. Hiding or inactivation cancels sampling cooperatively; a native read already in progress is not interrupted. Native accounting continues without periodic display aggregation. Returning establishes a fresh zero-rate baseline without resetting native volume. `EndpointTrafficStatistics` caches entries by stable ID and sorts those IDs; IDs may have gaps and do not index the native row array. Nonzero Unattributed appears first.

## Implementation and ownership

Statistics owns the native accounting, snapshot aggregation and display as separate responsibilities. The integrated release inherits the same implementation; `AppRoot` only connects the feature to the application's tabs. Other feature branches do not own or duplicate the meter.

Three patches follow the inherited UDP patches in `Build/features.json`:

- `hev-socket-meter-task.patch` observes successful socket results, including partial WAITALL and multi-message progress before an error or yield. Existing helper entries use a null observer and retain their I/O behavior.
- `hev-socket-meter-core.patch` owns the common worker/IP counters and connects both peer roles to the observed socket helpers. TCP retains peer references, including the address supplied by accept; UDP uses the actual message peer and caches its connected relay peer separately from the TCP control peer.
- `hev-socket-meter-server.patch` owns worker lifecycle integration and the public endpoint snapshot API.

Each worker writes its own counters for each IP. Ordinary I/O updates do not take a global counter lock or modify a shared Total counter. CAS coordinates new identity metadata and worker ownership. A standard pthread key binds worker storage to its native thread; storage becomes reusable only after that thread's native tasks stop, with accumulated values retained for the process lifetime.

Private 64-bit values are published through C11 32-bit atomic words with release/acquire ordering and sequence/epoch checks. Acquiring the initial epoch and both sequence reads orders the checks across sequence wrap. Readers retry until each worker part is coherent; this implementation does not impose a fixed retry limit. Writers do not wait for readers. Readers merge parts by IP, and Total merges the same endpoint data. Separate Total and row calls are not one simultaneous snapshot while traffic is changing. Allocation and pthread internals are not claimed to be lock-free.

`hev_socks5_server_endpoint_stats()` fills two non-null outputs: `received` means peer In and `sent` means peer Out. `hev_socks5_server_endpoint_rows(nil, 0)` queries required capacity, including ID 0, using identity metadata without reading counters. A copy call packs up to the supplied capacity into caller-owned `HevSocks5EndpointStats` rows and returns the current required count. Stable IDs are independent of packed-array positions. No registry pointer escapes through the API.

The view performs one capacity query and one bounded row copy per sample, then publishes one local dictionary snapshot. Native addresses are decoded only when an ID first enters the visible sampler cache; existing labels are reused without another lookup. Concurrent registration can defer some row updates across multiple samples; cached rows remain while later samples retry the bounded copy. This UI copy bound does not limit the native coherent-counter retry loop.

## Design rationale and resource cost

Worker-local counters remove shared per-I/O Total updates. Registration, allocation and snapshot merging still have costs. Process-lived storage grows with distinct IPs and the workers that used them. The visible-and-active gate avoids periodic snapshot, rate, sorting and formatting work while the tab is hidden or the scene inactive. Counters and publication tags have finite range, and large values lose precision when converted to Double for display.

## Verification contract

`Tests/SocketIO/` defines the native endpoint-I/O contract: both peer roles and address families, connected-address normalization and lookup fallback, unspecified peers, distinct TCP control/UDP relay peers, authentication and rejected input, partial frames, cancellation, successful message prefixes, peeks, worker concurrency, packed rows and stream/splice behavior. The Statistics audit composes this contract with the declared UDP prerequisite; inherited UDP fixtures remain part of the composed-engine validation. Statistics-owned test entry points initialize a meter worker before inherited fixtures run. Compile aliases preserve those fixtures' original substituted I/O boundaries. Meter helpers and real socket tests execute the observed paths directly. The host fixture provides the same distinct loopback peers on Linux and macOS and restores any addresses it adds. For composed lifecycle checks, Statistics supplies its reviewed worker digest while the lifecycle owner retains the Stop assertions. The restart fixture observes all four workers' first accept wait before its three Stop/Start cycles; only that fixture links the readiness observer.

The retained `traffic_statistics_model.swift` and per-IP model tests cover elapsed-time deltas, resets, large counters, SI thresholds and independent decimal rounding controls. `BridgeTests.swift` imports the actual new C ABI. The sampling replay executes the actual view sampling body with controlled rows, recorded state publication and address-decoding counts; historical per-row and eager-decoding negative controls remain required. It also checks packed rows with noncontiguous IDs. `SamplingTaskTests.swift` additionally replays the actual task body with real Swift task cancellation, controlled clocks/sleep and scripted native snapshots to check half-second boundaries, delayed execution, clock changes, actual elapsed-time rates, hidden/inactive entry, cancellation and fresh re-entry baselines. These are model/ABI checks, not SwiftUI render or scheduling measurements. The separate UI audit requires exactly one passed test, no failures, skips or expected failures, and a valid complete result summary before publishing success.

`Tests/Statistics/ui_audit.py` retains the Simulator test builder and checks the preserved table, formatter and sample method while enforcing the visible/active display gate and next-boundary delay. Its XCTest exchanges real IPv4/IPv6 SOCKS/UDP traffic, derives expected peer directions from the independent client's wire buffers and destination echo, and checks Total/IP tables, scrolling, orientation and Stop/Start retention. The first measured greeting reuses the readiness connection because closing it without a greeting can produce a counted rejection reply. Simulator execution requires the actual Apple toolchain; source checks or Linux model passes do not substitute for it.

## Operation and limitations

The inherited UDP fixed-port, multiple-unknown-peer restriction remains. Statistics does not change routing, prove remote delivery or identify a device behind a shared IP. The Statistics-only branch preserves the upstream lifecycle, including its early-Stop race; the separate ServerControl feature supplies that correction.

Physical iOS 27 SideStore standalone and LiveContainer guest operation, device resource measurements and non-Linux native runtimes require separate execution evidence. A configured minimum iOS version or a successful source build does not establish those results.
